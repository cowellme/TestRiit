## 2. Схема данных и серверная логика

| # | Требование | Статус | Где / комментарий |
|---|------------|--------|-------------------|
| 2.1 | Учётный номер: только цифры и латинские буквы, до 32 символов | ✅ | `Bakcend/Bakcend/Models/Technic.cs` — regex `^[a-zA-Z0-9]+$` + `[MaxLength(32)]` в сеттере; продублировано `validationRules` в диалоге DevExtreme |
| 2.2 | **Учётный номер должен быть уникальным** | ⚠️ | Уникальный индекс есть и входит в миграцию `InitialCreate` (`IX_Equipment_AccountNumber`, unique). Осталось: **(а)** для существующей БД (созданной ранее через `EnsureCreated`) пересоздать её (`docker compose down -v && docker compose up -d --build`) — иначе `Migrate()` упадёт на существующих таблицах; **(б)** при попытке вставить дубликат сейчас возвращается общий `BadRequest` с техническим текстом `ex.Message` — лучше перехватывать `DbUpdateException` и отдавать `Conflict` «Учётный номер уже существует» |
| 2.3 | Наименование: произвольные символы, до 256 символов | ✅ | `Technic.cs` — `[MaxLength(256)]` + проверка в сеттере; валидация в форме DevExtreme |
| 2.4 | Тип техники — выбор из словаря (отдельная таблица, столбцы ID и Наименование) | ✅ | `Bakcend/Bakcend/Models/TechnicType.cs` — таблица `TechnicTypes` (Id, Name). На клиенте тип выбирается из `/api/technicType` (lookup-колонка и `dxSelectBox` в форме) |
| 2.5 | Наименование типа до 128 символов | ✅ | `TechnicType.cs` — `[MaxLength(128)]` + проверка в сеттере |
| 2.6 | Связь «техника → тип» на уровне БД (внешний ключ) | ⚠️ | В `Technic.cs` есть `TechnicTypeId`, но навигация/`[ForeignKey]` отсутствуют — в БД **внешнего ключа нет** (целостность не гарантируется). В ТЗ явно не требуется, но рекомендуется: вернуть навигацию или задать связь в `OnModelCreating` (JSON-цикл больше не грозит — `Equipments` удалён) |
| 2.7 | Словарь пуст при старте сервера → записать 3–5 позиций | ✅ | Двойная защита: `HasData` входит в миграцию (заполняет при создании БД) + `DatabaseInitializer` (`Services/DatabaseInitializer.cs`) при **каждом** старте проверяет `if (!db.TechnicTypes.Any())` и добавляет 5 позиций |
| 2.8 | Комната размещения: целое от 1 до 1000 | ✅ | `Technic.cs` — `[Range(1, 1000)]` + проверка в сеттере; `dxNumberBox` с min/max и range-валидацией на клиенте |
| 2.9 | **Ограничение: не более 2000 записей в БД** | ✅ | `TechnicService.Add`/`AddRange` — проверка `CountAsync >= 2000` → исключение, контроллер отдаёт 400 с текстом. **Проверено сквозным тестом 11.11.2026:** 1995 тестовых вставок довели БД до 2000, 2001-я отклонилась (400, «Достигнут лимит…»), тестовые записи удалены. Нюанс: в `AddRange` условие `>= 2000` отклоняет и партию, приходящую ровно в 2000, — правильнее `> 2000` |
| 2.10 | CRUD API для техники | ✅ | `Bakcend/Bakcend/Controllers/TechnicController.cs` — GET (список/по id), POST, PUT, DELETE; цепочка Controller → Service → Repository |
| 2.11 | API справочника типов | ✅ | `Bakcend/Bakcend/Controllers/TechnicTypeController.cs` — GET всех типов. (POST/PUT/DELETE нет, хотя `ITechnicTypeService` их объявляет — для ТЗ достаточно GET) |
